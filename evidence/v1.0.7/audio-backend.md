# Audio and backend verification — 23 October 2026

The published GitHub Pages `audio.js` was fetched during this audit and contains procedural engine, wind, cockpit system movement/caution, nearby jet/flyby, gun, explosion and directional missile-warning sounds. These are original synthesized sounds, not recorded DCS audio.

Two defects were corrected: a destroyed engine retained powered idle beds (and stale burner state could retain powered noise); switching into a pilot with historical gun shots could produce a spurious gun burst. Powered beds now respect engine health/fuel/death and gun cues require a new shot for the same pilot. Aerodynamic wind remains for a fuel-starved gliding aircraft. Dry engine layers saturate at military throttle; the independently controlled afterburner flag adds the wet layers.

`node --test tests/audio-mixing.test.js tests/threat-audio.test.js tests/flight-speed-cues.test.js` passed 14 assertions covering mix balance, finite values, cockpit attenuation, powered-engine shutdown, directional proximity, system transition debounce, caution priority, and differentiated threat urgency.

`node tests/audio-browser.cjs` (with a local HTTP server on port 8033, or `BASE` pointing to another server) passed Chromium's real OfflineAudioContext rendering and live AudioContext/analyser checks. `audio.json` records PCM peak/RMS measurements. Audible scenarios generated nonzero finite PCM below full scale; mute/death produced zero PCM; burner RMS exceeded dry, and cockpit RMS was lower. Event voices were scheduled and cleaned up. A running live AudioContext produced nonzero analyser samples. Noise is stochastic, so subsequent measurements vary. **This is functional audio rendering/playback evidence, not human listening, speaker/headphone validation or a perceptual mixing review.**

The published `server-client.js` was fetched and still has `SERVER_ENDPOINTS = Object.freeze([])`. A server-authoritative public endpoint is not enabled. Existing PeerJS friend-room code is separate from the optional authoritative Node/Cloudflare backend; neither code presence nor these tests establishes cross-network multiplayer performance.

Local backend checks passed: 12 Node server tests including actual WebSocket clients/browser adapter, Wrangler dry-run bundle, and local Cloudflare workerd with six real WebSocket clients. Smoke checks covered CORS allowlist, six unique pilots with runway starts, seventh-player rejection, server-owned simulation, finite state, spoofed identity rejection and malformed-packet closure. The local run advanced 126 ticks / 2.10 simulation seconds and reported 11,573 uncompressed snapshot bytes with permessage-deflate negotiated. This is not a public deployment, mobile test, measured public latency or uptime claim. The release coordinator reruns against the final simulation/build before publishing.

Deployment remains blocked by missing configured Cloudflare authentication/verified account: no Cloudflare token environment names or standard local Wrangler auth directories were present. No account, credential, persistent access or deployment was created. The account's Free-plan status and a public workers.dev endpoint remain unverified; the frontend therefore keeps shared-server controls disabled.
